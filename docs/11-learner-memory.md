# 11 — Learner Memory

## Purpose
Define what learning history is retained, how it is updated, and how it influences future practice.

## Memory Categories
- Learner profile and preferences
- Goals and target level
- Skill estimates
- Recurring error patterns
- Vocabulary knowledge/retrieval state
- Pronunciation observations
- Scenario history
- Successful corrections and reuse
- Review recommendations

## Memory Lifecycle
Capture signal → validate → aggregate → update learner state → apply to future recommendations → decay/archive when appropriate.

## Evidence
Memory should be evidence-based. A single noisy event must not create a strong permanent belief.

## Retrieval
Only relevant memory should be injected into a session. Memory must be summarized rather than indiscriminately sending complete historical conversations.

## User Controls
Users should be able to view meaningful learning data, correct relevant profile information, request deletion/export where supported, and understand why recommendations occur.

## Retention
Retention periods are defined by privacy requirements and product necessity. Raw conversation content should not be retained longer than needed.

## Acceptance Criteria
- Memory categories are explicit.
- Updates are evidence-based.
- Retrieval is relevance-limited.
- User controls exist for applicable data.
- Retention and deletion rules are enforceable.
